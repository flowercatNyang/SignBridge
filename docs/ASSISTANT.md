# LLM 번역·비서 기능 실행

기존 단축키 메뉴에 **LLM 비서**를 추가했습니다. 수어 단어 인식 결과 또는 직접 입력한 한국어를 서버에 전달해 번역 후보·추가 질문·실행 명령으로 받습니다. 번역과 실행 내용을 확인한 뒤 Android의 시계/문자 앱으로 전달합니다. NVIDIA API를 호출하는 방식이므로 휴대전화나 PC에 LLM 가중치를 설치할 필요는 없습니다.

## API 키 입력 위치

이 PC에는 빈 `backend/.env`를 만들어 두었습니다. 두 번째 줄에 발급받은 키를 입력하세요.

```dotenv
NVIDIA_API_KEY=발급받은_실제_키
```

`backend/.env`는 Git에서 제외됩니다. 다른 PC나 새 clone에서는 다음 명령으로 템플릿을 복사한 뒤 키를 넣으세요. 기존 설정이 있다면 덮어쓰지 마세요.

```powershell
Copy-Item backend/.env.example backend/.env
```

기본 모델은 NVIDIA API의 `nvidia/nemotron-3-super-120b-a12b`입니다. 이전 기본 모델은 실제 호출에서 410 Gone을 반환해 교체했습니다. 해당 모델 이용 권한이 없거나 다른 모델을 쓰려면 `NVIDIA_MODEL`을 수정하세요. 키와 모델/모드 설정 변경 후 서버를 재시작합니다. 운영체제 환경변수로 설정한 값이 `.env`보다 우선합니다.

## 백엔드 실행

저장소 루트에서 Python 3.10 이상으로 실행합니다. 백엔드는 표준 라이브러리만 사용하므로 모델 학습용 PyTorch나 MediaPipe를 설치하지 않아도 됩니다.

```powershell
python -m backend.server
```

`http://127.0.0.1:8000/health`에서 상태를 확인할 수 있습니다. API는 `POST /v1/interpret`이며 서버가 스마트폰 기능을 직접 실행하지는 않습니다. API 키가 없으면 설정 안내를 반환하며 실제 요청을 보내지 않습니다.

이 PC에서 `python` 명령이 Windows Store 바로가기인 경우, 실제 Python 실행 파일을 사용하세요. Codex 내장 Python으로 실행하는 예:

```powershell
& 'C:\Users\sejee\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -m backend.server
```

## 앱 연결

Flutter 2.8 / Dart 2.15 및 Android 빌드 환경은 기존 앱과 동일합니다.

```powershell
cd apps/mobile
flutter pub get
flutter run
```

앱에서 **메뉴 → LLM 비서 → 서버 연결 설정**을 엽니다. 서버 주소는 경로 없이 입력합니다.

| 실행 환경 | 백엔드 주소 |
|---|---|
| Android 에뮬레이터 | `http://10.0.2.2:8000` (Android 기본값) |
| PC 웹 브라우저 | `http://127.0.0.1:8000` |
| USB 연결 Android 기기 | 아래 reverse 설정 후 `http://127.0.0.1:8000` |
| 같은 Wi-Fi의 Android 기기 | LAN 설정 후 `http://PC의_IP:8000` |

USB 기기는 PC의 다른 터미널에서 `adb reverse tcp:8000 tcp:8000`을 실행합니다. 이 방식은 백엔드를 기본 loopback 주소로 유지할 수 있습니다.

Wi-Fi 연결은 `backend/.env`의 `HOST=0.0.0.0`, `ASSISTANT_ACCESS_TOKEN=직접_만든_충분히_긴_랜덤_문자열`을 설정한 뒤 서버를 재시작합니다. 앱의 **서버 연결 토큰**에도 같은 값을 입력하세요. Windows 방화벽과 기기 간 접속이 허용되어야 합니다. 인터넷에 이 개발 서버를 직접 공개하지 마세요. 배포에는 HTTPS와 적절한 사용자 인증/사용량 관리가 필요합니다.

로컬 HTTP는 Android debug/profile 빌드에서만 허용합니다. release는 HTTPS 서버를 사용합니다. iOS 네이티브 실행 기능은 미구현이며 HTTP 연결 예외도 추가하지 않았습니다.

웹 확인:

```powershell
flutter run -d chrome --web-port 5300
```

다른 웹 포트를 사용하면 `.env`의 `CORS_ORIGINS`에 실제 origin을 추가하고 서버를 재시작하세요. HTTPS 웹페이지에서는 HTTP 서버 호출이 차단될 수 있습니다.

## 키 없이 시험하기

`backend/.env`에서 `LLM_MODE=mock`으로 바꾸고 서버를 재시작하세요. 앱에 **모의 응답 · 실제 LLM 번역 아님** 표시가 나옵니다. 모의 모드는 아래 세 요청과 간단한 추가 질문 흐름만 시험하는 고정 응답입니다.

- 알람 예시 버튼: `오전 7시에 기상 알람 설정해줘`
- 문자 예시 버튼: `엄마에게 늦을 것 같다고 문자 작성해줘`
- `알람 설정해줘` 입력 → 추가 질문 → `오전 7시` 답변

모의 모드에서도 **확인 후 실행**을 누르면 Android의 실제 시계/문자 앱을 엽니다. 자동으로 문자 발송하지는 않습니다. 실제 LLM을 사용하려면 `LLM_MODE=nvidia`로 되돌리세요.

## 지원 범위와 사용 방법

### 개발자 버튼으로 수어 조합 시험

기존 **단축키 실행 → 개발자 모드** 아래의 **LLM 수어 조합 테스트**에서 `보내다`, `늦다`, `일어나다`, `8` 등을 누를 수 있습니다. 기존 `테스트: 엄마` 같은 단축키 버튼은 즉시 기기 기능을 실행하고, 새 조합 패널의 `엄마` 버튼은 라벨만 쌓습니다. 조합 후 **조합을 LLM 비서로 보내기**를 누르면 비서 화면으로 이동하며 아직 API나 기기 기능을 실행하지 않습니다.

비서 화면에서도 **개발자 모드**를 켜면 같은 조합 버튼이 나타납니다. 누른 순서를 입력란에 모으고 `input_type=gloss`로 실제 카메라 인식 결과와 같은 API에 전달합니다. **마지막 단어 삭제**, **조합 비우기**, 직접 편집을 지원합니다. 개발자 모드에서는 카메라를 제거합니다. 동일 버튼을 두 번 누르면 라벨도 두 번 추가합니다.

예시:

- 문자: `엄마 → 나 → 늦다 → 보내다`
- 알람: `오전 → 8 → 시 → 일어나다 → 알람 → 설정`

이 순서는 소프트웨어 시험용 라벨 조합이며 검증된 한국수어 문장 예시는 아닙니다. **입력 완료 · 해석하기**를 누르고 번역 후보를 확인합니다. 최초 수어 라벨은 확인 질문을 거치므로 질문에 `맞아요`라고 직접 입력하거나 필요한 정보를 보완해 다시 해석합니다. 이후 **확인 후 실행**에서 알람/문자 작성 화면을 엽니다. 키와 백엔드 연결이 필요합니다.

위 두 조합과 확인 답변을 실제 NVIDIA API로 시험해 `compose_message`와 오전 8시 `set_alarm` 명령 생성을 확인했습니다. 후속 답변에서 원래 요청을 잊던 문제는 번역 후보와 질문을 실제 대화 턴으로 함께 전달하도록 수정했습니다. 번역 문장 자연스러움·정확성은 여전히 평가 대상이며, 이번 시험에서 실제 기기 기능은 실행하지 않았습니다. 백엔드 회귀 테스트 17개는 통과했습니다. 버튼/화면 테스트는 추가했지만 Flutter SDK가 없어 실행하지 못했습니다.

버튼은 모델의 영상 인식·신뢰도·경계 검출을 대신하는 시험 입력입니다. 카메라 모델의 지원 단어가 늘어난 것은 아닙니다. 번역·질문·명령 생성·기기 실행 경로를 시험하는 용도입니다. `LLM_MODE=mock`은 이 임의 라벨 조합을 번역하지 않으므로 실제 LLM 시험에는 `LLM_MODE=nvidia`를 사용하세요.

- **한국어 직접 입력**: 단어 확대 없이 비서 흐름을 먼저 시험합니다.
- **수어 인식 라벨 입력**: 라벨을 직접 입력하거나 **수어 입력 시작**으로 카메라를 켭니다. 카메라 모델은 기존 5단어만 인식합니다. 새 표현을 입력해도 영상 인식 능력이 늘어나는 것은 아닙니다.
- 카메라 입력은 75% 이상 후보를 누적하고 같은 표현이 계속 유지되면 중복 추가하지 않습니다. 인식 내용을 수정한 뒤 **입력 완료 · 해석하기**를 누르면 카메라를 제거하고 서버로 전송합니다. 앱이 배경으로 이동해도 비서 촬영을 종료합니다.
- 의미가 불명확하면 추가 질문을 표시합니다. 질문에 답해 재요청하며, 새 주제는 **새 요청**으로 시작합니다.
- 최초 수어 라벨 입력은 LLM이 확신하더라도 서버가 실행을 막고 번역 후보 확인 질문을 제공합니다. 단독 단어 분류 결과에 없는 문법 정보를 확실한 것으로 취급하지 않기 위한 처리입니다.
- 번역 후보와 실제 실행 인자를 별도로 확인합니다. 입력을 바꾸면 이전 실행 후보를 무효화합니다. 실행 후에는 같은 명령을 자동 재실행하지 않습니다.
- 알람: 24시간 시각·이름·반복 요일 지원. 반복 없음은 다음 해당 시각의 시계 알람입니다. **특정 날짜/상대 시간 예약은 지원하지 않습니다.** 시계 앱에서 실제 설정을 확인하세요. 알람에는 진동을 요청합니다.
- 문자: 사용자가 지정한 이름과 정확히 일치하는 연락처를 조회합니다. 번호가 없거나 여러 개이면 실행을 중단합니다. 연락처 권한만 필요하며 문자 작성 화면에서 직접 전송합니다.
- 병원 검색·수리 접수·iOS 실행·수어 영상 출력은 이번 범위에 포함하지 않았습니다.

## 번역의 현재 한계

LLM 프롬프트는 한국수어와 한국어의 문법 차이, 정보 누락, 모호한 주어/대상/시간을 다룹니다. 하지만 단어 라벨만으로 표정·공간 지시·부정 등 누락된 의미를 복원할 수 없습니다. 자연스러운 문장을 정확한 번역으로 보장하지 않습니다.

프롬프트의 예시는 **소프트웨어 출력 형식 예시**이며 농인 사용자와 검토된 한국수어 문장 데이터가 아닙니다. 검토된 글로스/문장 쌍과 의미 보존 평가를 다음 작업으로 추가해야 합니다. 앱의 추가 질문은 현재 한국어 텍스트입니다. 최종 업무 지원 앱을 위해서는 검토된 수어 안내도 필요합니다.

현재 서버는 JSON 출력 프롬프트와 엄격한 응답 검증을 사용합니다. 모델이 형식을 지키지 않으면 실행 명령을 반환하지 않습니다. 유효한 JSON이어도 의미가 정확한지는 별도 평가 대상입니다.

인식된 텍스트/라벨과 추가 질문 기록은 NVIDIA API로 전송합니다. 원본 영상과 연락처 전화번호는 서버에 보내지 않습니다. 서버는 대화 기록을 저장하지 않고 앱 메모리에만 유지합니다.

## 검증

```powershell
python -m unittest discover -s backend/tests -v
cd apps/mobile
flutter analyze
flutter test
```

핵심 파일은 `backend/assistant.py`(프롬프트·검증·NVIDIA 호출), `backend/server.py`(HTTP API), `apps/mobile/lib/src/assistant_page.dart`(입력·확인 화면), `assistant_client.dart`(응답 검증), Android `MainActivity.kt`(시계·문자 연결)입니다. 새 Python/Flutter 패키지 의존성은 추가하지 않았습니다.

실제 API 키 입력 후 NVIDIA로 알람 명령 생성, 문자 초안 생성, 모호한 수어 라벨 입력을 시험했습니다. 알람·문자 JSON 생성은 성공했습니다. 모호한 라벨에서 LLM이 주어를 임의로 확정하는 사례가 있어 최초 수어 라벨은 반드시 확인 질문을 거치도록 보완했습니다. 이 테스트는 실제 기능 실행이나 한국수어 번역 품질 검증이 아닙니다.

Python 모델·앱 연결 테스트 5개, 기존 JavaScript 특징 테스트 15개는 통과했습니다. 백엔드 구문과 Android manifest XML도 확인했습니다. Flutter/Dart SDK가 없는 환경이므로 앱 테스트는 작성했지만 실행하지 못했으며, Android 빌드와 실기기 기능도 확인이 필요합니다.

공식 참고: [NVIDIA LLM API](https://docs.api.nvidia.com/nim/reference/llm-apis), [Android 알람·문자 Intent](https://developer.android.com/guide/components/intents-common).
