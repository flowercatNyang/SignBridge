## 경로와 기능 통합

SexyInwon은 앱이 저장소 루트에 있고 Project는 `apps/mobile`에 있습니다. 새 Java 서비스·카메라 파이프라인·로고·테스트·진단 도구를 모두 `apps/mobile` 아래에 배치했습니다. 루트에 중복 Android 또는 Flutter 테스트 프로젝트를 남기지 않았습니다.

- SexyInwon의 홈·기기/기록/설정 데모 화면·로고와 PiP/백그라운드 카메라 구조를 반영했습니다.
- Sejun의 LLM 백엔드·요청/응답 검증·날짜 알람·13개 클래스 설정·두 ‘위’ 구분·모델 내보내기는 보존했습니다.
- MainActivity의 PiP/서비스 생명주기와 날짜 알람/문자/볼륨 처리를 한 파일에 통합했습니다.
- 단어 수집과 승인을 분리했습니다. 백그라운드 및 PiP에서도 단어만으로 전화·지도·볼륨 기능을 실행하지 않습니다.

## 입력 흐름

1. 홈의 카메라 시작 또는 메뉴의 단축키 실행에서 단어를 모읍니다.
2. 전경 입력은 **입력 완료 · LLM 비서로 보내기**로 전달합니다.
3. 백그라운드 입력은 알림으로 앱에 돌아온 뒤 **백그라운드 입력 가져오기**로 전달합니다. 이 버튼은 현재 LLM 입력과 이전 실행 후보를 대체합니다.
4. LLM 비서 진입/입력 가져오기 시 서비스 촬영을 중지합니다.
5. **입력 완료 · 해석하기** 후 질문에 답하고, 표시된 요청에 대해서만 그렇다/틀리다 또는 화면 버튼으로 승인/재입력합니다.

서비스는 프로세스 메모리에 최대 2000자까지만 입력을 보관합니다. 프로세스 종료 시 입력은 사라집니다. 백그라운드에서는 그렇다·틀리다를 승인 명령으로 처리하지 않으며 입력에도 추가하지 않습니다.

백그라운드 입력도 신뢰도 85% 이상의 같은 라벨이 3회 연속 관측되어야 추가되고, 단어 사이에는 손을 0.8초 이상 내려야 합니다. 화면이 보이지 않는 상태에서 시스템이 카메라 서비스를 종료하면 사용자가 앱에서 다시 시작해야 합니다.

- 백엔드 테스트 20개 통과: 모의 응답과 로컬 서버를 사용하며 실제 NVIDIA API/전화/문자를 호출하지 않았습니다.
- Python 앱 자산·전처리/모델 계약 5개, 단어 구성 1개, 네이티브 통합 계약 3개 통과.
