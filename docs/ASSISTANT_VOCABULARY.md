# SignBridge 비서용 어휘 후보안

선정일: 2026-10-26. 기준 자료: `data/processed/ksl_word_dictionary.json`의 3,000개 항목(고유 한국어 표기 2,771개).

이 문서는 기존 사전에서 고른 **100개 WORD ID 후보**와 목록에 없는 필수 표현을 구분합니다. 영상의 의미·수어 변이형·데이터 수량을 검수하기 전에는 최종 학습 클래스로 확정하지 않습니다. 모델·어휘 설정·앱 라벨은 이번 정리에서 수정하지 않았습니다.

## 선정 기준

- 대상·행동·시간·상태·확인에 반복 활용되는 표현 우선.
- 지명·기관명·특정 연락처 이름은 GPS·연락처 선택으로 보완하고 어휘 수를 무작정 늘리지 않음.
- 동일 한국어 표기의 서로 다른 WORD ID는 자동 병합하지 않음. 아래 대표 ID는 임시 후보이며 실제 영상을 보고 선택/변이형 관리를 확정.
- 어휘 사전에 있다는 사실은 해당 학습 영상·관절 시퀀스가 확보되어 있다는 뜻이 아님.
- P1 50개 먼저 검수하고 P2 50개를 확장. 기존 아프다·위·아래·회사·엄마는 모두 P1에 포함.

## 별도 확보할 필수 표현

다음 **16개 한국어 의미 항목**은 현재 3,000개 사전에 정확히 일치하는 표기가 없습니다. 실제 한국수어에서 어떤 단위/표현으로 구현되는지 먼저 확인하고, 다른 데이터셋 검색 또는 추가 촬영을 진행합니다. 임의의 WORD ID를 배정하지 않습니다.

- 확인·수정: 아니다, 취소, 다시
- 연락: 전화, 문자, 보내다, 늦다
- 알람: 알람, 설정, 오전, 오후, 시, 분
- 시간·검색: 오늘, 내일, 찾다

P1 50개와 이 16개는 **초기 검수 목표 66개 항목**입니다. 실제 클래스 수는 변이형 및 표현 단위 검토 후 정합니다.

추가 확장 17개(동일하게 사전의 정확한 표기 없음): 목요일, 토요일, 날씨, 약국, 배(사전 조회 표기: 배), 열, 기침, 집, 도착하다, 기다리다, 예약, 변경, 메모, 저장, 삭제, 알림, 약.

즉 기존 후보 100개 + 별도 확보 의미 항목 33개를 중기 어휘 계획으로 삼되, 한 번에 전부 학습하지 않습니다.

## 의미 검수가 특히 필요한 항목

- 신체의 팔 `WORD1147`과 숫자 8의 팔 `WORD2639`는 구분합니다.
- 숫자의 영 `WORD2631`, 일 `WORD2632`, 이 `WORD2633` 등은 숫자 타입과 값으로 정규화합니다. 원래 WORD ID/수어 라벨도 보존합니다.
- 위 `WORD2100`는 사용자 확인에 따라 장기 위입니다. 방향 위는 상부 `WORD2576`로 구분하고, 앱에는 각각 위(내장)·위(방향)으로 표시합니다.
- 일어나다는 `WORD1273`, `WORD1379` 등, 자다는 `WORD1377`, `WORD1378`, `WORD1544` 등 여러 ID가 있습니다. 기상/기립 및 변이형 여부를 검수합니다.
- 숫자 십의 `WORD2641`, `WORD2642`, 일요일의 `WORD0257`, `WORD0337` 등도 실제 표현을 확인합니다. 목록에는 임시 대표 ID 하나만 실었습니다.
- 그렇다·동의·거절을 맥락과 무관하게 실행 확인/취소로 매핑하지 않습니다.
- 점등·소등은 원래 조명 관련 의미를 보존합니다. 스마트폰 화면/전원 제어 단어로 임의 재라벨링하지 않습니다.
- 한국어 사전 표기를 단순 나열한 예시는 한국수어 문법 예시가 아닙니다. 농인 사용자와 표현·문장 수준을 검토합니다.

## 연결할 기능과 구현 범위

| 영역 | 활용 목표 | 필요한 추가 작업 |
|---|---|---|
| 연락 | 상태를 설명하고 문자 작성/연락 요청 | 기존 문자 기능 활용, 필요한 행동 어휘 확보 |
| 알람·일정 | 기상 알람, 반복, 일정/약 복용 알림 | 현재 시각·요일 알람만 지원. 날짜·캘린더·알림 기능 별도 개발 |
| 병원·생활 도움 | 증상 정리, 의료기관 검색, 상담/통역 요청 | 검색 API·검토된 안내 기준 필요. 증상만으로 진단/진료과 확정 금지 |
| 이동 | 주변 장소 검색과 길찾기 | 현재 회사 길찾기를 일반 장소 검색으로 확장 |
| 먹거리 | 주변 식당/카페 검색 | 장소 검색 및 사용자 선택 연결 |
| 기기·조명 | 카메라/연동 조명 등 | Android 기능 또는 외부 기기 API를 별도로 구현 |
| 날씨 | 날씨 조회와 생활 안내 | 실제 예보 데이터 연동; 덥다/춥다를 질환 등으로 임의 해석하지 않음 |
| 생활 요청 | 수리·예약·변경·메모 | 업무별 상태/입력 항목·실행 도구 개발 |

LLM은 입력에 없는 연락 대상·시간·부정·의도를 임의로 보충하지 않습니다. 의미가 불분명하면 질문하고, 지원하지 않는 기능을 완료했다고 응답하지 않습니다.

## 코드 적용 시 체크

1. 원본 라벨과 실제 학습 데이터의 대응 및 도메인/촬영자별 수량 확인.
2. `modules/vocabulary.py`를 새 검수 목록으로 확장하고 재학습. 기존 전문가 자료를 줄이지 않음.
3. 단어 누적 로직을 `shortcutCommands`의 기존 5개 명령에 종속되지 않게 분리.
4. 숫자의 원래 라벨과 정규화 값 보존. 신체 팔/숫자 팔, 방향 위/장기 위 등 동형 한국어 표기를 의미별 구분.
5. ONNX·설정·라벨·사전을 함께 내보내고 Android/Web 전처리·출력 순서 검증.
6. LLM에는 라벨뿐 아니라 출처/숫자 타입/명시적으로 확인한 정보도 전달. 단어 수 확장과 연속 수어 문장 이해는 별도 평가.
7. 초기 66개 검수 후 실제 사용 요청과 오류를 기준으로 나머지 후보의 순위 조정.
