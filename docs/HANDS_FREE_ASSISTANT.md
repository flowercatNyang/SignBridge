# 한 화면 수어 대화

수어 카메라 화면 안에서 입력·LLM 대화·확인을 계속합니다. 인식 후 별도 LLM 화면을 열거나 전송·승인 버튼을 누를 필요가 없습니다. 카메라는 화면 위에 고정되고 최신 질문/실행 계획은 바로 아래에 표시됩니다.

## 사용 흐름

1. 서버 연결 설정에 백엔드 주소와 연결 토큰을 넣고 저장합니다. NVIDIA API 키는 계속 서버의 `backend/.env`에만 둡니다.
2. 수어 단어를 차례로 입력하고 마지막에 **그렇다**를 합니다. 현재 모은 단어를 LLM에 보냅니다.
3. LLM의 질문이 같은 화면에 나타납니다. 추가 정보는 수어로 입력한 뒤 **그렇다**로 전송합니다.
4. 번역 후보가 맞는지 묻는 질문에는 새 단어 없이 **그렇다**로 동의할 수 있습니다. 필요한 정보가 부족하면 LLM이 추가 질문합니다.

확인 수어는 입력창을 ‘그렇다’로 바꾸지 않습니다. 화면의 **원래 요청**에 최초 문구를 유지하고, 확인 요청의 `text`에도 그 원문을 보내며 `input_type=confirmation`으로 확인 신호를 구분합니다. 추가 답변을 수어로 입력한 경우에는 새 답변을 보내고 원래 요청/질문은 대화 기록에 유지합니다.
5. 실행 계획이 표시된 뒤 손을 내려 인식을 해제하고 다시 **그렇다**를 하면 그 계획을 한 번 실행합니다.
6. **아니다/틀리다**는 모은 단어·미확정 계획·현재 요청의 대화 문맥을 폐기합니다. 같은 화면에서 새로 입력합니다. 이전 대화 표시만 남고 실행 계획은 남지 않습니다.

현재 배포 모델의 거절 라벨은 **틀리다**입니다. 앱은 **아니다/아니오** 라벨도 같은 취소 신호로 처리하지만, 새 ‘아니다’ 동작을 학습한 것은 아닙니다. 다른 동작의 인식은 모델 재학습/배포가 필요합니다.

## 제어 신호와 중복 방지

그렇다/아니다/틀리다는 일반 요청 단어에 붙이지 않습니다. 요청 대기 중에는 추가 입력을 처리하지 않습니다. 전송에 썼던 그렇다를 계속 유지해도 다음 번역이나 실행을 승인하지 않으며, 응답 확인 후 손을 0.8초 이상 내린 다음 새 확인 동작을 해야 합니다. 입력 중인 새 단어가 있으면 그렇다는 실행 승인이 아니라 새 내용 전송으로 동작합니다.

실행 계획은 호출 전에 소비하므로 외부 앱에서 돌아오거나 같은 그렇다를 반복해도 다시 실행하지 않습니다. 문자는 기존과 같이 문자 앱의 작성 화면을 열며, 실제 발송은 해당 앱에서 확인합니다. 백그라운드 수어 인식은 기존처럼 단어를 모을 뿐, 숨겨진 상태에서 LLM 기능을 자동 실행하지 않습니다.

## 연결 설정 유지

페이지 간에 연결 설정을 공유합니다. Android에서는 서버 주소와 기기 KeyStore 키로 AES-GCM 암호화한 연결 토큰을 저장하므로 앱을 재시작해도 다시 읽습니다. 기기 복원 등으로 암호화 키를 사용할 수 없으면 토큰 재설정을 안내합니다. 웹/기타 미리보기에서는 연결 설정을 앱 세션 동안 공유하며 토큰을 브라우저 영구 저장소에 쓰지 않습니다.

설정 읽기가 늦게 끝나도 그 사이 사용자가 수정한 값을 덮어쓰지 않습니다. 앱에는 NVIDIA API 키를 저장하지 않습니다.

## 개발자 모드와 검증

### 확인 단계의 원문 보존과 서버 호환

- 서버는 확인 요청의 원문과 대화 기록의 첫 요청이 일치하는지 검사합니다. 기록이 없거나 원문이 바뀐 확인 요청은 거부합니다.
- 기존 APK가 `text=그렇다`와 대화 기록을 보내더라도 서버가 원래 요청을 복원해 LLM에 `confirmation=true`와 함께 전달합니다. 따라서 **서버를 먼저 업데이트하고 재시작**한 뒤 앱을 업데이트하세요.
- 확인 요청이 실패하면 원문과 직전 질문을 유지해 손을 내린 뒤 다시 그렇다로 재시도할 수 있습니다. 실패한 확인을 새 요청 ‘그렇다’로 바꾸지 않습니다.
- Lightning에는 JSON 출력 모드를 요청합니다. 파서는 완전한 JSON 객체 또는 전체를 감싼 JSON 코드 블록만 허용하며, 설명문 속 명령 추출, 잘린 JSON, 중복 키/여러 JSON 객체는 거부합니다. 기존 실행 명령 검증은 유지합니다.
- ‘엄마 나 아프다 → 그렇다 → 전달 여부 질문 → 그렇다’ 회귀 테스트에서 두 번째 요청도 원문인지를 검사합니다. 실제 NVIDIA API에서도 원문 요청과 확인 요청의 2단계 응답을 확인했습니다. 실제 기기 기능은 실행하지 않았습니다.

개발자 모드의 단어 버튼도 실제 인식 라벨과 같은 대화 상태 처리를 사용합니다. 따라서 그렇다 버튼은 전송/승인을, 아니다/틀리다 버튼은 취소를 시험합니다. 일반 모드에서는 카메라 입력과 확인 수어를 사용합니다.

주요 회귀 테스트는 `apps/mobile/test/hands_free_assistant_test.dart`, 연결 저장 로직 테스트는 `assistant_connection_test.dart`입니다. 테스트는 모의 LLM과 가짜 기능 실행기를 사용하며 실제 API·알람·문자를 호출하지 않습니다.

Flutter 소스와 Android 네이티브 저장 코드가 바뀌었으므로 **APK를 다시 빌드해 설치해야** 합니다. 백엔드 재시작만으로 이미 설치된 앱의 화면/제어 동작은 바뀌지 않습니다. 모델 가중치와 백엔드의 사용자 수정 사항은 이번 작업에서 바꾸지 않았습니다.

```bash
cd apps/mobile
flutter pub get
flutter test test/hands_free_assistant_test.dart test/assistant_connection_test.dart
flutter build apk --debug
```

빌드된 `build/app/outputs/flutter-apk/app-debug.apk`를 휴대폰에 재설치합니다. Android SDK가 준비된 개발 환경에서 실행해야 합니다.

이번 Mac에서는 Flutter 브라우저 회귀 테스트 23개와 백엔드/로컬 HTTP 테스트 26개가 통과했습니다. 실제 카메라 인식률, Android KeyStore의 기기별 동작, 외부 알람/문자 앱 실행은 실제 휴대폰에서 추가 확인해야 합니다. 이 환경에는 Android SDK가 없어 APK 빌드/설치는 수행하지 않았습니다.
